## 3. Supabase 구조

프로젝트: `mveldownctofvhwcgnzz` (`https://mveldownctofvhwcgnzz.supabase.co`)
기존 매장 테이블(`used_stock`, `used_stock_meta`, `current_status`)은 **건드리지 않고** 게시판용 테이블만 추가합니다.

### 테이블

| 테이블 | 컬럼 | 설명 |
| --- | --- | --- |
| `ai_board_members` | `email`(PK), `created_at` | **열람 허용 이메일 목록**. 앱은 직접 읽지 못하고 함수로만 확인 |
| `ai_board_posts` | `id`, `user_id`, `category`, `author`, `title`, `content`, `is_pinned`, `created_at`, `updated_at` | 글. `is_pinned` = 맨 위 고정 |
| `ai_board_comments` | `id`, `post_id`(FK, 글 삭제 시 CASCADE), `user_id`, `author`, `content`, `created_at` | 댓글 |

인덱스: `created_at desc`, `category`, `(is_pinned desc, created_at desc)`, `(post_id, created_at)`.

### 트리거 · 함수

- `ai_board_set_user_id()` — insert 시 `user_id`를 `auth.uid()`로 강제 (앱이 다른 사람 이름으로 못 넣게)
- `ai_board_touch_updated_at()` — update 시 `updated_at` 자동 갱신
- `ai_board_is_member()` / `ai_board_whoami()` — 로그인 JWT의 이메일이 허용 목록에 있는지 확인 (SECURITY DEFINER, `authenticated`만 실행 가능)

### 보안 (RLS) 구조

- 3개 테이블 모두 **RLS 켬**. `anon`(비로그인)은 테이블 권한 자체가 `revoke` 되어 있어 데이터 요청이 통째로 막힙니다.
- `select` = 로그인 + 허용 이메일(`ai_board_is_member()`)인 경우만.
- `insert` = 허용 이메일 **그리고** `user_id = auth.uid()` (내 글만).
- `update` / `delete` = **자기 글만** (`user_id = auth.uid()`). 다른 사람 글은 화면에도 수정·삭제 버튼이 뜨지 않습니다.
- `ai_board_members`는 `anon`/`authenticated` 모두 권한 `revoke` — 목록 자체를 못 읽고 함수로만 판정합니다.
- 저장소에 들어 있는 키는 **공개용 publishable 키**입니다. 이 키만으로는 RLS를 통과할 수 없어 데이터가 새지 않습니다. (관리용 `service_role` 키는 절대 저장소에 넣지 않습니다.)

### 계정

- 로그인 계정: **`roos0200@gmail.com`** 하나 (필요하면 허용 목록에 이메일을 추가하고 Auth에 사용자를 만들면 됩니다).

### 🗓 일정 (`#/issues`) — 2026-11-28 추가

러버블 앱 `yescom-game-hq.lovable.app/missions`(진행 중) · `/history`(완료 기록)의 **2순위 장기 개인·매장 일정**을 게시판 안으로 옮겼습니다. **DB는 같은 Supabase 프로젝트의 `issues`를 그대로 씁니다** — 새 테이블·복제 없음, 러버블과 같은 데이터가 양쪽에 보입니다.

- **요약**: `7일 이내 N` · `전체(진행) M` · `기한 초과 K` + `+ 등록`.
- **서브 탭**: `진행 중` / `완료 기록`(러버블의 "완료 이슈 보기"에 해당).
- **빠른 등록**: `+ 고객예약` · `+ 금전` · `+ 법무` · `+ 일반` — 누르면 그 분류가 미리 선택된 등록 폼이 열립니다.
- **필터**: 전체 · 오늘 · 7일 이내 · 고객예약 · 금전 · 법무 · 매장 · 세금·행정 · 재고 · 기타 (모바일은 한 줄 가로 스크롤).
- **목록 카드**: `분류 · 상태 · 중요도` 칩 + D-day(오늘 / D-N / N일 지남 / 일정 없음), 제목, `예약 12.30(수) 23:18` 또는 `목표 07.01`, 다음행동(`→ …`), 관련금액, `수정` · `완료` 버튼. 정렬은 기한 초과 → 급한 날짜 → 중요도 → 최신 순.
- **완료 처리**: `완료` → 처리결과(선택) 입력 모달 → `status='완료'`, `is_active=false`, `completed_at` 기록. 완료 기록은 **지워지지 않습니다**.
- **완료 기록**: 검색창(제목·다음 행동·처리결과) + 분류 필터 + **완료일별 묶음**(2026년 10월 10일 · N건) + 처리결과 표시.
- **등록·수정 폼**: 제목* · 분류* · 목표일(`due_date`) · 예약일시(`scheduled_at`) · 현재상태(대기/진행중/확인필요/완료) · 중요도(높음/보통/낮음) · 다음행동 · 관련금액 · 처리결과.
- **컬럼**(실측, 14개): `id`(identity) · `title` · `category` · `status` · `priority` · `due_date`(date) · `scheduled_at`(timestamptz) · `next_action` · `amount`(bigint) · `result_note` · `is_active`(bool) · `created_at` · `updated_at` · `completed_at`. **`user_id` 컬럼은 없습니다** — 저장할 때 넣으면 오류가 납니다.
- **값**: 분류 `고객예약`·`금전`·`법무`·`매장`·`세금·행정`·`재고`·`기타` / 상태 `대기`·`진행중`·`확인필요`·`완료` / 중요도 `높음`·`보통`·`낮음`.
- **진행/완료 구분 기준**: `status = '완료'`면 완료 기록, 나머지는 진행 중. `is_active`만 보면 예전에 `완료` 처리된 행이 일부 `true`로 남아 있어 9건으로 잘못 세집니다(2026-11-28 실측: 진행 4건 · 완료 26건 = 30건).
- **시간대**: `scheduled_at`·`completed_at`은 UTC로 저장하고 화면에는 **KST**로 보여 줍니다(예: `14:18Z` → `23:18`). 예약일시 입력칸은 `datetime-local` 값은 KST로 해석해 저장합니다.
